Prototype guide

FindBack — interactive prototype

High-fidelity prototype using shared client-side state. Persona actions persist across pages and across personas. Click into any of the four user journeys below; each screen has a mockup-nav at the bottom with Previous / All journeys / Next links.

Source of truth: PRD FR-1..FR-39, EXPERIENCE.md (behavior), DESIGN.md (visual). The mockups below are a prototype of the product — not a redesign.

Claim demo item (Active Member flow): Found Black Backpack — reported by Sam, Main Library study carrel 4C, open status, no existing claim from Maya. Maya can sign in → open this item → Submit a claim → the claim becomes Pending, appears in My Claims, and shows up in Riley's Pending Claims queue. Use this item to walk UJ-1 end-to-end without needing to first reject any other seed claim.

Theme & accessibility

Toggle Auto / Light / Dark in the top bar. Light and dark use the same brand tokens; status colors rebalance for dark backgrounds.

The four journeys

UJ-1 Maya — "I lost my wallet and want it back" Member → Member → Admin

Reports a lost wallet, browses Found Items, finds a match (use the seeded Found Black Backpack — rpt_backpack_found), submits a claim, gets it approved, and receives it back.

1. Landing→ 2. Sign in→ ↘ 2a. Forgot password→ 2b. Reset link sent↖ 3. Listings (member)→ 4. Item detail (no relationship)→ 5. Submit claim→ 6. Claim thread→ 7. Admin reviews claim→ 8. Admin approves→ 9. Items awaiting return→ 10. Confirm returned→ 11. Returned

UJ-2 Sam — "I found a phone and want to return it" Member → Admin

Reports a found phone, sees incoming claim messages, watches admin approve, records the physical return.

1. Sign in→ 2. Report found item→ 3. My reports→ 4. Item detail (reporter view)→ 5. Claim thread (incoming message)→ 6. Admin reviews claim→ 7. Admin approves→ 8. Admin confirms returned

UJ-3 Alex — "I want to sign up" Public → Admin

Registers a new account, waits in Pending, gets approved by an administrator, and signs in as an Active member.

1. Landing→ 2. Register→ 2b. Validation errors→ 3. Confirmation→ 4. Pending account banner→ 5. Admin: pending registrations→ 6. Admin: approve→ 6b. Admin: reject with reason→ 7. Rejected login state

Deactivated state: 08-deactivated-account.html

UJ-4 Riley — "I'm an administrator" Admin

Reviews registrations, approves a single claim, handles competing claims with auto-rejection, confirms a physical return, reviews audit trail, closes inappropriate content.

1. Admin dashboard→ 2. Pending registrations→ 3. Approve→ 4. Pending claims→ 5. Single claim review→ 6. Approve confirmation→ 7. Competing claims review→ 8. Reject confirmation→ 9. Rejected claimant view→ 10. Items awaiting return→ 11a. Confirm returned (default)→ 11b. Confirm returned (substitute)→ 12. Audit trail→ 13. Close inappropriate content

UJ-5 Anonymous Visitor — "I'm looking for something I lost" Public → Sign-in CTA

Visits the public landing, browses and filters the public Lost & Found summary, hits the authentication boundary on any item detail or authenticated action, then chooses to sign in or register.

Anonymous visitors see only type, category, location, date, and status. Item detail pages, claims, reports, member dashboard, my-reports, my-claims, and all administrator pages are gated.

1. Public landing→ 2. Browse Lost & Found (anonymous)→ ⇄ 3. Search & filter (keyword, category, location, type)→ ↘ 4a. Auth boundary — item card → Sign in→ 4b. …or Create an account→ 5. Registration confirmation→ 6. Pending approval (awaiting administrator)

Anonymous CAN: view landing · browse public summaries · use keyword/category/location/type filters · see item card meta only · navigate to Sign in · navigate to Register.

Anonymous CANNOT: open item detail · submit a claim · post claim messages · create Lost/Found reports · view My reports / My claims / Member Dashboard · access any administrator page. Attempts redirect to Sign in with ?next= preserved.
